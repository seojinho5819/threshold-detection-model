# CAN 데이터 계약서 (Data Contract)

> **대상**: 에이전트(로봇 단말) 개발자
> **목적**: AI 이상탐지 모델이 사용하는 **디코딩된 CAN 데이터의 형식·주기·전달 방식**을 확정한다.
> **작성일 기준**: 2026-06-11 · 상태: **초안(확정 필요 항목 ⬜ 표시)**

---

## 0. 한 줄 요약

에이전트는 raw CAN 프레임을 **DBC로 디코딩한 "표 형태 신호"** 로 변환해,
**(A) 실시간으로 MQTT** 에 publish 하고, **(B) 매일 1회 파일**로 떨군다.
**두 경로는 완전히 동일한 스키마·단위·주기**를 따른다.

```
CAN 버스(raw 프레임) ──[에이전트: DBC 디코딩·정제]──> 표 형태 신호
                                                       ├─ 실시간 → MQTT (추론용)
                                                       └─ 일배치 → 데일리 파일 (학습용)
```

모델은 raw CAN을 직접 보지 않는다. **디코딩 결과 표의 품질이 곧 모델 품질**이다.

---

## 1. 반드시 지켜야 할 3대 제약

1. **스키마 일치** — 실시간(MQTT)과 데일리 파일의 컬럼/키·단위·타입이 100% 동일.
2. **주기 일치** — 학습 파일의 샘플링 주기 = 실시간 전송 주기. (다르면 통계 Feature가
   흔들려 정상 데이터도 이상으로 오탐된다. 검증: 10Hz→2Hz 시 정상비율 99%→62% 하락.)
3. **정상만(학습 파일)** — 데일리 학습 파일에는 **고장/정비 구간을 넣지 않는다.**
   고장이 섞이면 모델이 그 고장을 "정상"으로 학습해 이후 못 잡는다.

---

## 2. 신호 스키마 (⬜ = 에이전트 개발자 확정 필요)

> 아래 신호 목록·단위·범위는 **현재 placeholder(합성 데이터 기준)** 이다.
> **실제 CAN 정의서에 맞게 확정**해 주세요. 신호가 바뀌면 모델은 재학습한다.

| 컬럼명(키) | 의미 | 단위 | 타입 | 정상범위(참고) | 필수 |
|---|---|---|---|---|---|
| `timestamp` | 샘플 시각 | ISO8601(ms) | string | — | ✅ |
| `rpm` | 엔진/모터 회전수 | rpm | float | ⬜ | ⬜ |
| `speed` | 주행 속도 | km/h | float | ⬜ | ⬜ |
| `battery_voltage` | 배터리 전압 | V | float | ⬜ | ⬜ |
| `motor_current` | 모터 전류 | A | float | ⬜ | ⬜ |
| `motor_temperature` | 모터 온도 | °C | float | ⬜ | ⬜ |
| `hydraulic_pressure` | 유압 | bar | float | ⬜ | ⬜ |
| `error_count` | 에러 카운트 | 개 | int | ⬜ | ⬜ |
| ⬜ (추가/삭제) | | | | | |

**컬럼명 규칙**: 영문 소문자 + 언더스코어. 실시간 JSON 키와 파일 헤더가 동일해야 함.

---

## 3. 타임스탬프 규약

- 포맷: `YYYY-MM-DD HH:MM:SS.fff` (ms 단위) 또는 ISO8601 (`2026-06-11T03:00:00.000Z`)
- 타임존: ⬜ UTC 권장 (혼선 방지). 로컬 사용 시 명시.
- **단조 증가**(시간 역행 없음), **일정 주기**, 중복 시각 없음.

---

## 4. 샘플링 주기

- 목표 주기: ⬜ ____ Hz  (현재 모델 가정: **10Hz**, `window_seconds=10`)
- 실시간·데일리 파일 **동일 주기**.
- 주기가 흔들리면(예: 네트워크 지연) 가능한 한 일정하게 유지. 큰 변동은 사전 공유.

---

## 5. 실시간 경로 (MQTT)

- 브로커: ⬜ 호스트/포트 (예: `mqtt://<host>:1883`)
- **발행 토픽**: `robots/<robot_id>/can`
- **페이로드**: 위 스키마의 한 샘플을 JSON 1건으로
  ```json
  {
    "robot_id": "robot-001",
    "timestamp": "2026-06-11T03:00:00.000Z",
    "rpm": 1524.3, "speed": 8.0, "battery_voltage": 47.6,
    "motor_current": 29.7, "motor_temperature": 56.3,
    "hydraulic_pressure": 126.5, "error_count": 0
  }
  ```
- `robot_id`는 페이로드에 포함 권장(없으면 토픽에서 파싱).
- **참고(에이전트가 구독할 수 있음)**: 추론 결과는 백엔드가 `robots/<robot_id>/health`
  로 다시 발행한다. (에이전트가 쓸 필요는 없으나 참고용)

---

## 6. 데일리 파일 경로 (학습용)

- 형식: ⬜ CSV 또는 Parquet (대용량이면 Parquet 권장)
- **파일명**: `YYYY-MM-DD.<ext>` (해당 날짜의 정상 운행분)
- **전달 위치**: ⬜ ____ (예: `data/daily/` 디렉토리 또는 공유 스토리지 경로)
- **컬럼 = 위 스키마와 동일**, 헤더 포함, UTF-8.
- 예 (`2026-06-12.csv`):
  ```
  timestamp,rpm,speed,battery_voltage,motor_current,motor_temperature,hydraulic_pressure,error_count
  2026-06-12 00:00:00.000,1524.3,8.0,47.6,29.7,56.3,126.5,0
  2026-06-12 00:00:00.100,1416.9,8.5,47.6,30.0,60.4,129.0,0
  ```
- 전달 주기: ⬜ 매일 ____ 시 (예: 새벽 02:00, 전일 데이터 마감 후)

---

## 7. 정제(cleaning) 요구사항 — 데일리 파일

에이전트가 떨구기 전 처리:

- ☐ 결측/NaN 처리 (보간 또는 해당 구간 제외)
- ☐ 타임스탬프 단조 증가·중복 제거·주기 유지
- ☐ 단위 일관성 (스키마와 일치)
- ☐ 센서 드롭아웃/통신 끊김 구간 제거
- ☐ **알려진 고장·정비 구간 제외** (학습 파일은 정상만)
- ⚠️ 단발 스파이크 노이즈는 **과하게 제거하지 말 것** (정상 변동까지 지우면 모델
  커버리지가 줄어 오탐 증가). 명백한 오류값만 정리.

---

## 8. (선택) 검증용 라벨 데이터 — 정비/장애 기록 연동

학습엔 라벨이 필요 없지만, **모델 검증**을 위해 "알려진 고장 구간"이 있으면 별도 제공:

| robot_id | 시작 | 종료 | 구분 | 비고 |
|---|---|---|---|---|
| robot-001 | 2026-05-03 14:00 | 2026-05-03 15:00 | 온도 과열 | 정비기록 #123 |
| ⬜ | | | | |

- 행 단위가 아니라 **구간(이벤트) 단위**로 소량이면 충분.
- 정비/장애 기록에서 가져오면 됨 (별도 수작업 라벨링 불필요).

---

## 9. 에이전트 개발자 확정 체크리스트

- ⬜ 실제 신호 목록·단위·타입 (2장)
- ⬜ 각 신호 정상범위 (선택, 참고용)
- ⬜ 샘플링 주기(Hz) (4장)
- ⬜ MQTT 브로커 호스트/포트 (5장)
- ⬜ 데일리 파일 형식·전달 위치·전달 시각 (6장)
- ⬜ 타임존 (3장)
- ⬜ (선택) 검증용 고장 구간 기록 제공 가능 여부 (8장)

> 위 항목이 확정되면 `config/feature_config.yaml`의 `raw_signals`·`sample_rate_hz`를
> 실제값으로 교체하고 첫 실데이터 학습을 진행한다.
